### Post-Phase-3 enhancement: Product default location (2026-09-27)

A new optional field on Product, not a change to how stock is tracked. Adds `ci_products.default_location_id` — "ตำแหน่งจัดเก็บหลัก / ตำแหน่งที่แนะนำตอนรับเข้า" — a preferred/recommended storage Location used only to preselect a Location when receiving. **Actual stock location remains determined exclusively by the append-only `ci_stock_movement_lines` ledger via `ci_stock_balances`, unchanged by this feature.** A Product may still have stock in many Locations at once; a stock transfer or a confirmed receipt at a different Location never rewrites `default_location_id`, and setting/clearing the default never touches stock.

- **Migration:** `20260927140000_ci_product_default_location.sql` adds `ci_products.default_location_id uuid` (nullable, no backfill — every pre-existing row is `NULL`) with a composite FK `(default_location_id, warehouse_id) references ci_locations(id, warehouse_id)` — same-warehouse only, and skipped entirely by `MATCH SIMPLE` when null, which is what keeps it optional — plus a partial index for the deactivation-guard lookup below. `ci_create_product`/`ci_update_product` (both live in `ci_private`, retroactively moved there from `public` by an earlier migration; their already-published `public` SECURITY INVOKER wrappers are untouched) validate a supplied default the same way every other receiving/transfer RPC validates a Location — exists, same warehouse, active — and `NULL` always clears it with no validation. Signatures are unchanged; the field travels inside the existing `p_data` jsonb payload.
- **Deactivation guard:** `ci_set_location_active` gained one new check — deactivating a Location is blocked with `CI_LOCATION_IS_PRODUCT_DEFAULT` while it is the `default_location_id` of an active Product. It does **not** auto-clear the Product's default, and does not touch stock balances; the existing active-children and has-stock guards are unchanged. An inactive Product's stale default never blocks deactivation.
